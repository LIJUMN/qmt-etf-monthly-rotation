> **用法**：看到想试的方向在下表里判过负，**先看「解封条件」这列**。
> 满足条件就**直接重测**，不需要再问任何人——这是铁律 1 第 4 条的落地。

| # | 历史结论 | 当初的验证条件（只有在这个条件下成立） | 解封条件（满足就重测，别当禁令） |
|---|---|---|---|
| 1 | **布林带回归无效** | 53 品种**等权组合** + **20.5 年全样本**，仅 7/53 跑赢躺平 | ① **单标的**口径 ② **特定波动率区间** ③ **换带宽/均线参数** ④ 加**趋势过滤**后 —— 全部**未验证** |
| 2 | **额外止损掉收益** | **512480 单标的** + **全历史满仓 MACD**，试了 MA20 / MA60 过滤 | ① **ATR 动态止损** ② **移动止损（吊灯）** ③ **时间止损** ④ **分批减仓** —— 全部**未测** |

## 二、引擎事实（不能改，改了代码跑不通）

> **和上表的区别**：上表是「观点」，可以推翻；这张表是「引擎行为」，换什么参数都不变。
> **改动它们不会让 AI 更强，只会让代码跑不通**（v9 就是这么翻车的）。
> 判断方法：这条结论**换了标的、换了窗口、换了参数还可能成立吗？** **不会 → 是事实。**

| # | 事实 | 后果 |
|---|---|---|
| E1 | **回测里 `get_trade_detail_data` 返回值不可靠**（乱跳/时滞） | 回测**必须**用自带账本 `g.cash`/`g.shares`（实盘里才用真实持仓查询） |
| E2 | **回测参数四件套**：最大成交比例=**100%**（默认 0.05% 是头号元凶，会造成"只买不卖"）、滑点 0.1%、平昨平今佣金 0.025%、初始资金 100000（与代码 `g.cash` 一致） | 不对 → 回测成绩注水或策略退化 |
| E3 | **中文 print 会被 GBK 吞掉** | 日志必须纯 ASCII（文件编码 GBK，第一行 `#encoding:gbk`） |
| E4 | **取数必须传 `end_time`** | 不传 → 数据窗口冻结在历史末尾，信号永远不变 |
| E5 | **QMT 内置 Python 单线程**，官方明文禁止多线程/多进程 | 只能靠"少算"提速；重活放离线跑（见铁律 1 离线优先原则） |
| E6 | **QMT 内置只能纯内置**（2026-10 新规禁读写文件/联网） | 桥接类不可用是**合规限制**，不是能力限制；**离线环境不受此限** |
| E7 | **离线数据里混着「份额折算」与「涨跌停」**（2026-10-14 审计确诊）：同一只标的可能无预警地 1:2 / 1:4 / 1:10 拆分或反向合并（510180 在 2009-05-21、2013-12-23 各一次） | 用「单日跳变超阈值」判拆分 = 把**每个涨跌停日**都误判成拆分（全库误报 1324 次）。**必须按整数送转倍数判别**（下跳 <0.60 / 上跳 >1.70），且 `o/h/l/c/v` 同比例缩放。INDEX 一律不做 |
| E8 | **离线数据文件的主键会撞车**：`INDEX_000001`（上证指数）与 `STOCK_000001`（平安银行）code 都是 `000001` | 若用裸 code 当字典键，**上证指数会被静默覆盖丢弃**。必须用 `前缀_代码` 复合键 |
| E9 | **10 万本金 + 100 股整手 ⇒ 高价标的静默空仓**：价格 > ~998 元时 `int(100000/(px*1.00125)/100)*100 = 0` | 茅台（600519）在窗口内 **71.6%** 的交易日买不进；**基准同样被低估**（只剩 300 股 + 8.8 千闲置现金）。引擎不报错，成绩看起来「平坦」而非「失败」 |
| E10 | **总收益跨长度不可比**：8 年 +41% 与 2 年 +14% 摆在一张表里比 | 「样本外塌陷」有相当部分是**区间长度幻觉**。必须统一用**年化 CAGR** 横向比 |
| E11 | **回测取价口径由「复权方式」决定，且会静默降级**：`get_market_data_ex(dividend_type=...)` 的默认值是「跟随主图复权方式」；本地缺除权数据时，普通 `'front'` 会**不报错地退化成不复权原始价**。官方问答库原话：回测推荐用**等比前复权**，这样"无需考虑配股、增发带来的变化，始终以统一标准的价格进行买卖" | **回测一律 `dividend_type='front_ratio'`，并在回测参数面板把复权方式也选成「等比前复权」**。2026-10-14 那次翻车就是踩了这条：策略逻辑全对，净值被口径砍掉 31% |
| E12 | **存量 ETF 大面积做过「份额折算」（拆分），且除权数据常常缺失**：36 只 ETF 里 **15 只**有折算事件，8 只小额分红，只有 13 只干净。典型：513100 于 **2022-01-14 做 1:5 折算**（不复权价 5.192→1.015，成交量同步 ×5.7）；512480 半导体 2021-03-29 与 2026-07-03 各一次 | 回测不处理折算 → **那根K线变成假暴跌**，凭空吃掉账户一大块，还伪造巨额回撤。体检表：`数据与因子/_复权体检.csv`（15 只危险 / 13 只干净，干净的可直接回测） |
| E13 | **判据：ETF 单日涨跌幅不可能超过它的涨跌停**（主板 ETF ±10%，科创/创业板 ETF ±20%），指数无涨跌停 | **这就是最便宜的数据体检器**：单日跌破 -11%（主板）必有折算或数据错。已写进 v2 策略的 `guard()` 做实时报警。**另：回测前先跑一遍「买入持有」做对照**——513100 2019-06→2026-10 真值 **+344%**，若显示 **-11%** 就是缺折算数据，整个回测直接作废 |
| E14 | **nativeApi（xtquant 外接）在本机取数是死的，而且它根本没有回测引擎**（2026-10-14 本机实测三轮）：<br>① `from xtquant import xtdata` 成功（客户端自带 Python **3.6.8**，库在 `安装目录\bin.x64\Lib\site-packages\xtquant`）<br>② 行情服务 `127.0.0.1:58610` 有 `miniquote.exe` 监听，能连上<br>③ 但 `get_market_data_ex` **恒返回空 DataFrame**；`download_history_data` **返回 OK 却不落盘**（513100.DAT 始终 16,520 字节）；`get_divid_factors` **返回空**<br>④ 官方 nativeApi 示例页只有 `xtdata`（取数）+ `xttrader`（下单），**没有回测模块** | **回测只能走内置策略面板**。外部下载接口在 2026 新规下已形同虚设（正是 `qmt-debug-ops` 记的"外接客户端已停用"）。看到 nativeApi 链接不要以为换套 API 就能解决复权问题——**它和内置读的是同一份本地数据** |
| E15 | **QMT 有「两个数据仓」，且外接 API 读的是残缺那个**：<br>· `安装目录\datadir\` —— **3.3 GB，完整**（513100.DAT = 208,584 字节）<br>· `userdata_mini\datadir\` —— **残缺**（513100.DAT = 16,520 字节）<br>`xtdata.data_dir` 默认 = `../userdata_mini/datadir`；内置策略走的是前者 | 外接取数恒空。**内置回测其实是有数据的**，缺的只是**除权记录** |
| E16 | **QMT 本地「除权数据库」实际是空的**：`datadir\DividData` 与 `userdata_mini\datadir\DividData` **都只有 8 KB**（leveldb 骨架文件） | **这是 513100 及所有折算标的前复权失效的总根子**。修法只有一条：QMT 「数据管理」补下载**除权数据**。补齐前，任何代码、任何 API 都拿不到正确前复权价 |
